# 自社採用ページ（Google しごと検索 対応）

**公開先：`https://www.musasinokobetu.com/recruit/`**

求人媒体は全て、企業アカウントの開設に事業所確認（電話番号認証・事業所番号・法人確認）を要求します。
一方、**Google しごと検索（Google for Jobs）にはアカウント登録が存在しません**。
自社サイトのページに `JobPosting` 構造化データを置けば、Google がクロールして無料で掲載します。

このフォルダは、その採用ページ一式です。**サイトに置いた時点で求人が世に出ます。**

---

## 1. ファイル構成

```
recruit/
├── README.md               ← このファイル（サイトには不要。アップロード対象外）
├── index.html              ← 採用トップ（求人一覧・塾の紹介）
├── koushi.html             ← 個別指導講師（アルバイト・パート）
├── koushi-chuju.html       ← 個別指導講師（中学受験）
├── koushi-kokosei.html     ← 個別指導講師（高校生・英語／数学）
├── jimu.html               ← 教室運営・事務スタッフ（パート）
├── style.css               ← 共通スタイル（外部リソース依存なし）
├── sitemap.xml             ← Search Console 送信用
└── check_jobposting.py     ← 構造化データの検査（サイトには不要。アップロード対象外）
```

**アップロードするのは `.html` `.css` `.xml` の7ファイルだけ**です。
`README.md` と `check_jobposting.py` はリポジトリ側の管理用なので、サイトに置く必要はありません。

1求人1ページの構成です。Google しごと検索は「1ページに1求人」を前提としているため、
一覧ページ（index.html）には JobPosting を置かず、Organization のみにしています。

ページ内のリンクは全て相対パス（`./koushi.html` `./style.css`）です。
`/recruit/` 直下にまとめて置けば、そのまま動きます。

## 2. 設置手順

### ステップ1：`【要確認】` を実額に置き換える

各 HTML の先頭にある HTML コメントに、確定が必要な項目を書いてあります。

| ファイル | 確定が必要な項目 |
|---|---|
| `koushi.html` | ~~給与・交通費~~ 確定済み（1コマ90分 2,100円／事務給 時給1,400円／交通費 1日1,500円） |
| `koushi-chuju.html` | ~~給与・交通費~~ 確定済み（同上） |
| `koushi-kokosei.html` | ~~給与・交通費~~ 確定済み（同上） |
| `jimu.html` | ~~時給・交通費・業務範囲~~ すべて確定済み |

給与は全講師職・事務職とも **時給1,400円（授業1コマ90分＝2,100円）** で確定済みです。
交通費（1日1,500円まで）、支払日（当月末締め・翌月末払い）も確定済みです。
**このステップで直す項目はもう残っていません。** 次のステップへ進んでください。

**金額は本文の表と JSON-LD の `baseSalary` の2か所にあります。両方直してください。**
片方だけ直すと、検索結果の表示と実際のページで金額が食い違います。

### ステップ2：日付を更新する

各ページの JSON-LD にある `datePosted` を公開日に、`validThrough` を掲載終了予定日にします。
現在は `datePosted: 2026-08-02` / `validThrough: 2026-10-31` です。

**`validThrough` を過ぎると掲載が止まります。** 期限前に更新するか、募集終了ならページごと削除してください。

### ステップ3：検査を通す

```bash
python3 recruit/check_jobposting.py
```

必須項目の欠落、住所の不足、期限切れ、identifier の重複、`【要確認】` の残りを検出します。
期限は本日基準で判定し、残り14日以内になると警告します。
（`--date 2026-12-01` のように基準日を指定して先の状態を確認することもできます。）

### ステップ4：サイトへアップロードする

**サイトの構築方法によって手順が変わります。** 該当するものを選んでください。

#### A. レンタルサーバー（FTP・ファイルマネージャーが使える場合）

さくら・エックスサーバー・ロリポップ・お名前.com などの一般的なレンタルサーバー、
またはサーバー上に直接 HTML を置いている場合は、これが最も簡単です。

1. FTPソフト（FileZilla など）またはサーバー管理画面のファイルマネージャーで接続
2. 公開ディレクトリ（`public_html` `www` `htdocs` などサーバーによって名称が異なります）を開く
3. その直下に **`recruit` フォルダを新規作成**
4. 上記7ファイルをアップロード
5. ブラウザで `https://www.musasinokobetu.com/recruit/` を開いて表示を確認

> **既存ファイルを上書きしないよう注意してください。** `recruit` という名前のフォルダが
> すでにある場合は、中身を確認してから作業してください。

#### B. WordPress

WordPress でも、静的HTMLをサーバー上に直接置けば `/recruit/` で表示されます（上記Aと同じ手順）。
ただし WordPress のパーマリンク設定と衝突する可能性があるため、次のどちらかにしてください。

- **B-1（推奨）：FTPで `/recruit/` に直接置く**
  WordPress は実在するファイル・ディレクトリへのアクセスを横取りしないため、通常は問題なく表示されます。
  `recruit` という名前の固定ページ・投稿・カテゴリが**存在しないこと**だけ確認してください。存在すると衝突します。
- **B-2：WordPress の固定ページとして作る**
  各求人ページを固定ページとして作成し、JSON-LD をカスタムHTMLブロックで埋め込みます。
  デザインはテーマ側に合わせることになるため、`style.css` は使いません。
  この方式にする場合、HTMLからの移し替えは対応します。

#### C. Wix・Jimdo・Ameba Ownd・STUDIO などのサイトビルダー

**このケースでは任意のフォルダをアップロードできません。** 選択肢は3つです。

- **C-1：ビルダー上で採用ページを作り、JSON-LD だけ埋め込む**
  多くのビルダーに「カスタムコード」「HTML埋め込み」の機能があります。
  各求人ページに対応するページをビルダーで作り、そのページのカスタムコード欄に
  該当HTMLの `<script type="application/ld+json">` ブロックをそのまま貼ります。
  **本文の内容とJSON-LDの内容が一致していること**が条件です（食い違うとGoogleが掲載を止めます）。
- **C-2：サブドメインを立てる**
  `saiyo.musasinokobetu.com` を用意し、そこにこのフォルダを置きます。
  独自ドメイン配下なので、GitHub Pages のサブドメインより有利です。
- **C-3：現状の GitHub Pages のまま運用する**
  求人としては問題なく機能します。ただし canonical が
  `www.musasinokobetu.com/recruit/` を指しているため、**そのURLが存在しない状態だと
  Google がページを正しく扱えません。** この選択をする場合は、全ファイルの canonical と
  `sitemap.xml` を GitHub Pages のURLに戻す必要があります（戻す作業は対応します）。

### ステップ5：Google に登録する

1. [Google Search Console](https://search.google.com/search-console) で `musasinokobetu.com` を登録（所有権確認）
2. 「サイトマップ」から `https://www.musasinokobetu.com/recruit/sitemap.xml` を送信
3. [リッチリザルトテスト](https://search.google.com/test/rich-results)に各求人ページのURLを入れ、
   「求人情報」として認識されるか確認する
4. インデックス後、Google で「武蔵境 塾講師 求人」等を検索して掲載を確認

掲載までは通常、数日から2週間程度かかります。

> **robots.txt について**：サイトのルートに `robots.txt` がすでにある場合、
> そこに `Sitemap: https://www.musasinokobetu.com/recruit/sitemap.xml` の1行を**追記**すると
> 発見が早くなります。**既存の robots.txt を上書きしないでください。**
> サイト全体のクロール設定が入っている可能性があります。

### ステップ6：既存サイトから導線をつなぐ

トップページのメニューやフッターに「採用情報」のリンクを追加してください。
リンクがあると、Google のクロールが早くなります。

```html
<a href="/recruit/">採用情報</a>
```

## 3. GitHub Pages 側の扱い

このリポジトリをマージすると、GitHub Pages 側にも同じページが公開されます。
ただし**全ファイルの canonical が `www.musasinokobetu.com/recruit/` を指している**ため、
Google は本番ドメインのほうを正規のページとして扱います。重複コンテンツにはなりません。

つまり GitHub Pages 側は「本番に上げる前の確認用プレビュー」として使えます。
表示崩れやリンク切れは、そちらで確認してから本番へ上げるのが安全です。

**ただし、本番URLが存在しない状態が続くのは避けてください。** canonical の指す先が
404 のままだと、Google がどちらも正しく扱えません。本番へ設置するか、
設置しないと決めたなら canonical を戻すか、どちらかにしてください。

## 4. 他媒体への波及

この採用ページは、他の無料媒体への入口にもなります。

| 媒体 | 自社採用ページとの関係 |
|---|---|
| Google しごと検索 | **アカウント不要。構造化データだけで掲載される**（このページの主目的） |
| 求人ボックス | 自社サイトのクロール掲載あり。掲載申請が必要な場合があります【要確認】 |
| スタンバイ | 同上【要確認】 |
| Indeed | 企業アカウントで自社サイトを登録するとクロール対象になります |
| engage / Airワーク | 別途アカウント開設が必要（このページとは独立） |

公式ドメイン配下に置くことで、この経路の扱いが良くなります。
各社のクロール掲載の条件は変わることがあるので、掲載申請の要否は各社の最新情報で確認してください。

## 6. 応募導線について

現在の応募導線は**電話のみ**です（`tel:` リンク）。

メールアドレスまたは応募フォームを用意すると応募率が上がります。追加するなら次のいずれかです。

1. **メールリンク**（最も簡単）— `mailto:` を追加する。受信用アドレスの用意だけで済みます
2. **Google フォーム** — フォームを作り、応募ボタンのリンク先にする。無料で、応募内容がスプレッドシートに溜まります
3. **サイト側の問い合わせフォーム** — 既存サイトにフォームがあるなら、それを応募先にする手もあります

**2 を推奨します。** 応募者の連絡先・希望曜日・指導可能科目を最初から構造化して受け取れるので、
折り返しの電話が1回で済みます。フォームを作っていただければ、リンクの組み込みは対応します。
