# Indeed 運用戦略｜数学・英語講師の採用

**採用目標：数学講師・英語講師**
21本の求人票は、この目標に対して「手を替え品を替えて出す」ための素材です。
本ファイルは、それをどう出すかの運用ルールです。**投稿の前に必ずここを読んでください。**

---

## 1. 前提：Indeed で表示順が落ちる3つの原因

| # | 原因 | 対策 |
|---|---|---|
| 1 | **重複判定** — 同一企業・同一勤務地で本文の似た求人が並ぶと、片方が抑制される | 同時掲載を3本までに絞り、本文の類似度を機械的に管理する（第4節） |
| 2 | **鮮度の劣化** — 掲載から時間が経つと表示が減る | 4週で入れ替える。ただし同じ求人の再投稿を繰り返さない（第6節） |
| 3 | **応募率の低さ** — 表示されても応募されない求人は、さらに表示されなくなる | 職種名と冒頭3行で対象者を絞る。誰でも応募できる書き方をしない |

> **正直な注意**：Indeed の重複判定の具体的な基準は公開されていません。
> 本ファイルの類似度の閾値（0.45／0.60）は、**当方が安全側に設定した運用基準**であり、
> Indeed の公式基準ではありません。数値はあくまで相対比較の道具として使ってください。
>
> また、無料掲載の表示量には限りがあります。有料スポンサー求人と同じ露出は得られません。
> 本戦略は「無料枠の中で取りこぼさない」ためのものです。

## 3. 同時掲載ルール

### ルール1：同時に出すのは3本まで

無料掲載で4本以上並べると、重複判定を受けるか、表示が互いを食い合います。

### ルール2：3本の内訳を固定する

| 枠 | 役割 | 入れる求人 |
|---|---|---|
| **A枠** | 数学の主力 | 17／21／15／16 のいずれか1本 |
| **B枠** | 英語の主力 | 14／18／12 のいずれか1本 |
| **C枠** | 母数の確保 | 11／13／01 のいずれか1本 |

### ルール3：同じ枠の求人を2本同時に出さない

15・16・17・21 は互いに包含関係にあります。**同時に出すと重複判定の対象です。**
12・14・18 も同様、13・21 も同様です。

### ルール4：ハローワークに出す職種は Indeed に直接投稿しない

ハローワークの求人は Indeed へ自動転載されます。二重に出ると重複になります。
`04` `05` はハローワーク側の担当です（`recruitment/hellowork/README.md` 第3節）。
`06`（教室長候補）はどちらにも出しません。募集していないためです。

## 4. 類似度の検査（投稿前に必ず実行）

```bash
# 全21本の総当たり比較
python3 recruitment/indeed/check_similarity.py

# これから同時掲載する3本だけを検査
python3 recruitment/indeed/check_similarity.py --live 17 11 14
```

判定は3段階です。

| 類似度 | 判定 | 対応 |
|---|---|---|
| 0.60 以上 | 危険 | 同時掲載しない |
| 0.45 以上 | 注意 | 同時掲載するなら、どちらかの本文を書き分ける |
| 0.45 未満 | 問題なし | そのまま出してよい |

**現状（21本・210組）で危険はゼロです。** 注意は 19×20（世界史×日本史）の1組のみですが、
この2本は採用目標外でローテーション最後尾のため、同時に出ることはありません。

本文を書き換えたら、必ず再実行してください。

## 6. やってはいけないこと

| # | やってはいけないこと | 理由 |
|---|---|---|
| 1 | **同じ求人を停止→再投稿して鮮度を稼ぐ** | 再投稿の繰り返しは検知されます。別の求人に入れ替えてください |
| 2 | **本文を一部だけ変えた求人を並べる** | 最も重複判定を受けやすい形です。書き分けるなら構成から変えてください |
| 3 | **職種名を「講師A」「講師B」のように分ける** | 求職者が検索する語が入らず、表示されません |
| 4 | **職種名に「急募」「高収入」「★」を入れる** | 掲載ガイドライン違反で非掲載になります |
| 5 | **給与を「応相談」だけにする** | 同上。下限額は必ず記載してください |
| 6 | **4本以上を同時に出す** | 互いの表示を食い合います |
| 7 | **ハローワークと同じ職種を直接投稿する** | 自動転載と二重になります |
| 8 | **募集が埋まった求人を出したままにする** | 応募率が下がり、他の求人の表示にも影響します |

| 週 | 求人# | 表示回数 | クリック | 応募 | 面接 | 採用 | メモ |
|---|---|---|---|---|---|---|---|
| W1 | 17 | | | | | | |
| W2 | 17 | | | | | | |
| W2 | 11 | | | | | | |
| W3 | 17 | | | | | | |
| W3 | 14 | | | | | | |
| W3 | 11 | | | | | | |

数値は Indeed の管理画面（求人ごとの「パフォーマンス」）で確認できます。

**判断の目安**

- 表示は多いがクリックが少ない → **職種名**が悪い。書き換えて次のローテーションへ
- クリックは多いが応募が少ない → **冒頭3行と給与**が悪い。条件を見直す
- 応募は来るが面接に至らない → **応募資格の書き方**が緩すぎる。絞る
- 応募がゼロのまま4週 → その切り口は当地では効かない。ローテーションから外す

## 8. 各求人が「別物」である根拠

同じ塾の講師募集を21本出しても重複にならないのは、**実際に別の仕事だから**です。
求人票は以下の6点で書き分けてあります。小手先の言い換えではありません。

| 差別化の軸 | 例 |
|---|---|
| **職種名** | 「東京農工大学 受験対策の個別指導講師」／「大学受験数学の個別指導講師」／「高校受験の個別指導講師（英数国理社）」 |
| **冒頭の切り口** | 17は「母校の対策を教えませんか」／15は「求められるのは難問を解く力ではありません」／18は「英語はできる、で止まらない指導」 |
| **本文の構成** | 16は表組み中心、17は科目別の箇条書き、11は「内申／入試／志望校別」の3層構成 |
| **具体例** | 17は数IIIの計算量、15は答案の部分点、09は速さのつまずき4類型、18は自由英作文の添削 |
| **時間帯** | 09は16:40台中心、12・13・18は20:00-21:30中心、11は定期テスト前の増コマ |
| **応募資格の絞り** | 15・16・17は「記述答案の添削ができること」が必須、18は「自由英作文の添削」が必須、11・13は不問 |

**この6点を崩すと重複判定に近づきます。** 求人票を編集するときは、この軸を壊さないでください。

### 給与について（2026年8月に方針変更）

当初は職種ごとに単価差をつけていましたが、**全講師職を時給1,400円（1コマ90分＝2,100円）に統一**しました。
そのため、給与は差別化の軸として使えなくなっています。

- **重複判定への影響は軽微でした。** 統一の前後で最大類似度は 0.524 → 0.525、
  計画中の同時掲載3本組も 0.393 → 0.397 と、ほぼ変化していません。
  差別化は残る6軸が担っています
- **一方、採用面では効きます。** 18（早慶英語・自由英作文の添削）や
  15・16・17（数III＋記述添削）のような専門性の高い枠を、
  11（高校受験5教科・未経験可）と同じ単価で募集することになります。
  この層の応募が集まらない場合、**最初に見直すべきは単価**です
- 見直す場合は、専門性の高い枠だけ単価を上げてください。全体を上げる必要はありません

## 9. 投稿手順（各求人共通）

1. 該当する求人票の `【要確認】` を実額に置き換える
2. `python3 recruitment/indeed/check_similarity.py --live <その週の3本>` を実行し、問題なしを確認
3. Indeed で「求人を掲載」→ 無料掲載（スポンサー設定はオフ）
4. 求人票の「▼ Indeed 入力フォーム対応表」を各欄にコピペ
5. 「仕事内容」欄に `## 仕事内容（本文コピペ用）` 以下を全文貼り付け
6. 掲載後、第7節の表に週次で数値を記録
7. 4週経ったら停止し、ローテーション表の次の求人へ

## 10. ローカルから投稿する（推奨手順）

claude.ai やGitHub連携から起動したリモートセッションには、**ブラウザ操作のMCPが接続されていません**。
そのため Indeed への投稿は、`claude-in-chrome` MCP が使える**ローカルのClaude Code**で行います。

Mac のターミナルで、このリポジトリの直下から実行してください。

```bash
git pull
./recruitment/indeed/post_to_indeed.sh 17
```

スクリプトがやること。

1. `git pull` で求人票を最新化する（未コミットの変更がある場合は pull せず続行）
2. 貼り付け用のプレーンテキストを再生成する
3. 掲載中の求人と重複しないか検査する（`--live` を渡したときのみ）
4. 求人票の「▼ Indeed 入力フォーム対応表」から**依頼文を自動生成**する
5. 仕事内容の本文をクリップボードにコピーする
6. Claude Code を起動し、依頼文を渡す

### 週ごとの実行例

| 週 | コマンド |
|---|---|
| W1 | `./recruitment/indeed/post_to_indeed.sh 17` |
| W2 | `./recruitment/indeed/post_to_indeed.sh 11 --live 17` |
| W3 | `./recruitment/indeed/post_to_indeed.sh 14 --live 17 11` |
| W5 | `./recruitment/indeed/post_to_indeed.sh 21 --live 11 14`（17は停止後） |

`--live` に掲載中の番号を渡すと、**危険域（類似度0.60以上）の組み合わせがあれば投稿前に止まります。**

### 動作確認だけしたいとき

```bash
./recruitment/indeed/post_to_indeed.sh 17 --dry-run
```

Claude Code は起動せず、生成される依頼文を表示するだけです。

### 依頼文に含まれる歯止め

自動生成される依頼文には、次の制約が毎回入ります。

- スポンサー（有料掲載）は必ずオフ。課金画面が出たら停止して確認する
- 投稿するのは指定した1件だけ。他の求人を新規作成しない
- 既存の掲載中求人を編集・停止・削除しない
- 職種名に装飾語を足さない。給与を「応相談」に変えない
- ログイン画面が出たら認証を代行せず、ユーザーに依頼する
- 本文を要約・短縮せず、生成済みテキストをそのまま貼る

### 本文を直したくなったら

正本は `.md` の求人票です。`plaintext/` 配下は生成物なので直接編集しないでください。

```bash
# 求人票を編集したあと
python3 recruitment/indeed/to_plaintext.py 17
```
